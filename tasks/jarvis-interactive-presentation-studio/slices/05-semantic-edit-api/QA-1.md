## Findings

### BLOCKING
**B1 - `scene.restore_values` is a free-path write: any manifest-valid `props`/`data`, undeclared keys included, tier `control`, for either actor.**
`jarvis/domain/presentation_studio_edit.py:610-620` (`RestoreValues` branch of `_apply_one`) replaces the scene's whole `props`/`data` after only the reserved-key check, then the commit runs `check_scenes` (manifest validity and curated bounds of *declared* controls). It never asks "is every changed path a declared control?". The module docstring (l.20-21), the doc ("a change the declared controls cannot make is **not** a free path") and the tier table (tier 1 = a declared control) say the opposite.
Repro (`a5.py`, real `PrefabService`, `lab.counter` where only `props.label`, `data.count`, `props.mode` have controls):
- `control.set start_count 500` -> `refused value_refused` (curated max 100), as designed.
- `scene.restore_values {props:{accent:"#ff0000",label:"x"}, data:{count:5}}` (actor `brain`, commit) -> `applied`, `changed true`, `tier control`. `accent` has no control.
- `scene.restore_values {props:{}, data:{count:5, link:"https://evil.example/x"}}` -> `applied`; stored scene now `data.link = https://evil.example/x`. `link` has no control. `unknown_control` / `source_request` was the only door.
Impact: the semantic vocabulary is "closed" on paper but one op writes anything valid to a scene, labelled as the lowest tier, with no declared control. Slice 21 will expose the vocabulary to the voice brain (the plan lists `presentation_edit`); the single exception that makes the gate meaningless is the inverse op itself.
Fix (small): for `RestoreValues`, compute the set of leaf paths that differ from the current scene values and refuse `unknown_control` when one is not a declared (and not unsafe) control path of that scene at that point of the batch. Undo still works: each inverse is applied in the state right after the op it undoes, so the paths it changes are the ones that op changed (declared at that time; `scene.set_controls` inverse runs first when it was later in the batch). Add tests: restore touching an undeclared path is refused, the undo round trip of the whole vocabulary still passes. Alternative if the PM prefers: restrict `scene.restore_values` to a request whose first op set is exactly an undo (`basis == applies_at_revision`), but the path rule is simpler and local.

### POLISH
**P1 - undo is canonical-exact, not file-byte-exact (key order).** `_with_value`/`_values_inverse` rebuild props/data through `json.loads(canonical_json(...))` (sorted keys) while `dump_document` writes in insertion order. Repro (`a1.py undo_exact`): scene stored with `props {mode,label}`, `data {notes,history,count}`; edit then replay the undo record: canonical JSON equal, but file key order is now `props [label,mode]`, `data [count,history,notes]`, history item `{delta,ratio}` (was `{ratio,delta}`); file bytes differ modulo revision. Every edit also reorders keys of the edited scene. The doc says "byte for byte (compared by stored form)": the hedge is true, but "byte for byte" and the test name `..._restores_the_scenes_byte_for_byte` oversell. Fix: copy with `copy.deepcopy` instead of a canonical round trip, or reword to "canonically equal". Full 9-op compound batch undo (rename, reorder, remove, add at index, set_controls, list set, reset, source_request) and redo (undo of undo) are canonical-equal (`a4.py compound`).
