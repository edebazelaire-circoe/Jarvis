### Emitter design / limits

Synchronous `record` (derive id, validate, `put_nowait`), never raises; queue 1024, overflow drops the newest (causal prefix kept), one warning per episode; lazy drain task, 50 ms linger after wake-up, batches ≤ 32 via `append_many`; store error drops batch, error once per episode + recovery info; invalid event → warning with codec message; stop: refuse, drain ≤ 2 s, count/diagnose remainder, counters journaled. Limits: memory queue (hard kill loses not-yet-committed events; test proves committed ones survive `os._exit`); shared repository lock (an append serializes with other state writes for one FULL-sync commit); content > 8192 not recorded (diagnosed).

Linger evidence (scratch probe, real `JarvisCoreApplication`, instant scripted backend, 40 submits 200 ms apart, commit windows vs `submit()` windows): without linger 280 commits (1.1 events each), 40/40 submits and 40/40 turn bodies overlapped an event commit, i.e. the user-event commit landed inside `submit()`'s remaining state-DB awaits; with 50 ms linger 40 commits (8 events each), 0/40 submits and 0/40 turn bodies overlapped.
