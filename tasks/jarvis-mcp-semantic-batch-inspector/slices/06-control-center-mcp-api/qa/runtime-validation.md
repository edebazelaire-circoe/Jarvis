# Slice 06 — Runtime validation (Control Center MCP catalog API)

HEAD `7011125`, 2026-09-25. No source modified, nothing committed. Companion: `agent-trace-analysis.md`. Evidence: `evidence/` (`api/` = every HTTP response saved, `cli/` = brain launches, CLI streams, model-request tool definitions, runtime trace; `scripts/` = harness).

**Verdict: PASS with minor CONCERNS.** Every contracted availability transition was observed against a really launched brain. The catalog's tool lists and byte counts equal exactly what the CLI sent to the model. No secret appeared in any response. Two small contract precision points, both non-blocking (C1, C2 below).

## Environment

- Isolated Core `127.77.0.1:17683` and Control Center `127.0.0.1:17685`, both started from this worktree (`scripts/env.sh`, `start.sh`). `JARVIS_DATA_ROOT` and `JARVIS_RUNTIME_DIR` were in the scratchpad. The port guard refuses empty, 17653 and 17654. `JARVIS_SCENE_ENABLED` was unset so the settings API could toggle the scene. The browser tab was suppressed with a no-op `webbrowser.open`.
- **The real brain was launched by the Control Center itself** (`ClaudeLocalAgent.start()` at CC start, then `POST /api/agent/restart`). `JARVIS_CLAUDE_CLI` pointed to a QA wrapper, a native `.exe` built from pip's distlib launcher plus `scripts/brain_wrapper_main.py`. The wrapper does four things:
  - **removes `--chrome`**, so the brain never reached the user's browser. There is no env or setting for this, and it needed no source edit.
  - logs the argv the Control Center passed (`cli/brain-launches-argv.jsonl`; prompt and hook are truncated there).
  - execs the real `claude.exe` 2.1.282 with a **fake local Messages endpoint** (`scripts/fake_api.py`, port 17689, the same method as Slice 05) and an isolated `CLAUDE_CONFIG_DIR`.
  - tees stdout (`cli/stream-launch*.jsonl`).
- The MCP servers (`jarvis-display`, `jarvis-barehands`, `jarvis-console`) were the real ones, spawned by the real CLI from the configs the real code wrote.
- **Cost: $0.** Two trivial turns ("Dis juste bonjour.") were sent through `POST /api/agent/send` only to get the CLI to emit `system/init` and its first Messages request. Both were answered by the fake endpoint. No real model call was made.
- Everything started was stopped at the end: CC, Core, fake API, and the brain with its MCP children (checked by listing processes and ports). The live Jarvis (17653/17654) was untouched and still listening.

## Concerns (non-blocking)

- **C1 — Codex `advertised` is `false`, not `null` (MINOR, doc/test precision).** `CodexLocalAgent` has no permanent process: between turns its snapshot state is `ready`, and `advertised_from_agent_snapshot` returns `False` for any state ≠ `running` before it looks for the flag. So `null` only happens during a Codex turn. The unit test (`test_control_center_mcp_api.py:278`) uses a synthetic `state:"running"` Codex snapshot, which is the rare case. The displayed state (`disabled`) and `pending_restart:false` are correct either way. `false` is even literally true, since Codex is never launched with these servers. Contract §4.3 and §10.6 read as if Codex always gives `null`.
  - Repro: set `{cli:{agent:"codex"}}`, then `GET /api/mcp/tools` shows native servers with `advertised:false`.
  - Options for the PM: word the contract as "`null` while a Codex turn runs, `false` otherwise", or make Codex give `null` whenever the agent has no `display_mcp` attribute.
- **C2 — Uncoded 404 for a one-segment path (FLAGGED).** `GET /api/mcp/tools/jarvis-display` returns aiohttp's text `404: Not Found`, not `mcp_tool_unknown`. The 405 bodies are also plain text. The contract only codes `{server}/{name}`, so this is consistent. The Slice 07 inspector should only build two-segment URLs.
- **FLAGGED (not S6):** each brain stop logs `agent.exit` at **error** level (`returncode 1`), including intentional restarts and kills (3 entries in `errors.jsonl`). The wrapper may contribute (the process tree is killed through it), but this is not attributable to S6. Worth a look only if the live trace shows the same after a normal "Redémarrer le brain".
- **FLAGGED for S7:** `pending_restart:true` is also shown when the brain is simply stopped (per the formula). The inspector wording should say "(re)démarrer", not only "redémarrer".

## Not verified

- A real model call through the CLI (fake endpoint by design, $0). `--chrome` was stripped, so the `claude-in-chrome` server that the real brain also gets was not observed.
- `jarvis-drive` inside the brain's own `mcp_servers` (the isolated CLI config does not load user-scope servers). Its tool names were cross-checked against the operator's registration instead.
- `advertised:null` during a live Codex turn (it would need a real Codex model turn).
- `503 mcp_server_unavailable` / `mcp_catalog_unavailable` at runtime. Drive imports fine here and forcing a failure needs a source or environment change to the dependencies; unit tests cover it.
- The Control Center page UI itself (Slice 07 builds the inspector). The API was driven with the same routes and bodies the page's JS uses.
