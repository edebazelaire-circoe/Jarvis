# Decision Log

## Locked decisions

1. The page title is **Mémoire & connaissances**.
2. Primary product grouping is `Mémoire`, `Connaissances`, `Memory Center`.
3. Canonical Markdown memory stays the sole durable truth.
4. Derived indexes must always be visually/semantically labeled as derived or status-only.
5. Lexical recall remains the fallback and works without semantic retrieval.
6. Semantic retrieval exposes enablement, provider and explicit private-data permission; current provider vocabulary remains server-owned.
7. Raw recall timeout belongs in Advanced; an optional simple user-facing profile may summarize several low-level settings only if runtime semantics are explicitly defined.
8. Consolidation keeps candidate-first semantics. Manual candidate review remains first-class.
9. Knowledge sources show preference and runtime availability separately.
10. CodeGraph must not appear healthy merely because its toggle is on when no provider/repository is mounted.
11. Loadouts become editable through normal UI rather than read-only text telling the user to edit a settings file.
12. Loadout UI uses product concepts (agent/role, Memory, Private, Wiki, Code, Skills), not raw technical keys.
13. Architecture Settings owns communication topology; Memory & connaissances owns information-access policy.
14. Memory Center is a dedicated workspace. Notes, Candidates, Knowledge and Recall Test remain accessible.
15. Detailed index health is secondary. Low-level health codes, timings, Tencent mirror details and storage-source provenance move to Advanced diagnostics.
16. Credential values are never displayed here. Only configured/not-configured state is allowed, with a link to Connections.
17. The validated neon/glass mockups define visual language and composition only. Mockup data and unsupported buttons are not requirements.
