## Dynamic context and inactive templates

- The startup recent-context suffix reads `recent_turns[-12:]`, renders `kind: content`, and is part of the actual session instruction string. Preview without a conversation must show an explicit unbound context slot, not claim to be the literal sent prompt.
- Canonical `append_quiet_context` currently sends a user-role **data message** through low-level `append_message` without `response.create`. The separate `append_context_message` operation maps canonical DEVELOPER to the provider's system role; do not conflate these operations. Legacy `send_context` inserts a user message and requests a response; tool results also have their own message/response behavior. These are ordered conversation inputs, not initialization-template overrides. Show channel, role, operation correlation and response-trigger flag separately.
- `feed_runtime_instruction` currently sends a full replacement via `session.update`, serializes updates and waits for matching instruction ACK. A timeout returns UNKNOWN. Inspector must distinguish saved preview, last sent replacement, and last acknowledged replacement; it must not display “applied” just because Settings saved.
- `adapters/openai_agent.py::_SYSTEM_INSTRUCTIONS` and `config.py` / `runtime/factory.py` / `OpenAITTSBackend` belong to the older non-v2 entrypoint. `OPENAI_TTS_INSTRUCTIONS` / config `tts_instructions` is a real customization there, but does not configure current Realtime/Claude voice. These are inactive for the selected v2 runtime, not proven dead code.
- Handoff `templates/` and proposed prompt prose in task documentation are planning artifacts, with no discovered production builder reading them. Do not list them as effective prompts. The Agents panel's task prompt is a provider diagnostic truncated to 4000 characters; it is neither the initialization registry nor a reliable full effective backend prompt.

## Minimal descriptor and resolver

Use registry-backed descriptors around existing builders instead of a second independent prompt assembler. Each descriptor needs stable ID, runtime role, provider/model and compatibility applicability, source symbol/path, default revision/text, editable flag, declared variables, destination/channel, ordered composition operation (append/replace/message) and apply policy (next invocation/session or supported acknowledged update). Initial IDs can follow the real roles above, such as `voice.persona`, `voice.legacy_rules`, `voice.continuous_rules`, `realtime.verbatim`, `realtime.preamble`, `backend.claude.system`, `backend.turn_brief`; they are proposals, not implemented API names.

Resolution returns a structured application payload: selected layers in order, selected source for each value, rendered channel-specific text/messages and fingerprints. There is no one flat “effective prompt” that truthfully combines Claude system append, a user brief, a Realtime response replacement and quiet developer data. Settings can offer an ordered inspection view, with the exact selected invocation payload when its dynamic inputs are available.

Use the same resolved object at each actual send site and in preview. Fingerprint deterministic layer IDs/revisions, applicability, composition order and rendered static text. Keep a distinct invocation/render fingerprint for exact dynamic payloads when required, linked to its bounded source revision; do not put raw conversation text in normal metrics or label a static fingerprint as a hash of the entire sent conversation. Preserve exact whitespace/CLI transport normalization explicitly.

## Override persistence and application semantics

No supported editable prompt key was found in the current v2 `voice_stack` fields or Control Center settings write path. Existing customization includes code defaults/constructor injection, selected stack/model settings and older TTS instructions; do not silently import these as new prompt overrides or overwrite unrelated saved values.

Add a versioned, narrowly scoped overrides object through the existing atomic settings writer. Store only user override text plus its base revision and applicability key; absence means default, reset removes just that override. Preserve overrides for inactive modes/models and unknown future IDs during unrelated settings saves. Avoid materializing defaults into user settings. Shared persona edits should visibly show their actual multi-provider applicability; model switches must not transplant provider-specific overrides.

Validate declared placeholders, text bounds and editability before save/render. User data remains data, never parsed as a template. Keep dynamic source facts, tool schemas and programmatic runtime invariants read-only. If a static wrapper is editable, preserve required data slots structurally so an edit cannot accidentally remove the requested result or reorder authority-bearing channels. A stale base revision should remain visible as a customization conflict, not trigger automatic rewriting.

Default to next-session application for initialization layers. Explicit hot application is only available where the actual adapter supports it; current Realtime updates replace the full resolved session instruction text, so edits cannot send one isolated fragment as if it were an append. Claude resume remains an older applied snapshot until an actual new session/verified mechanism applies the revision. Do not restart or open billable sessions for a preview. Add Luna/Live descriptors only after their Tasks10/12 builders and capabilities exist.
