## Data and assertion discipline

1. Store fixture provenance separately for reported source text/time, derived relative ordering, and constructed event fields. Local event/session/task IDs are test IDs, not recovered provider IDs.
2. Use virtual clocks and controlled async release gates; preserve relevant causal order rather than sleeping85.7s. Keep source reported delays as historical metadata. New measured policy latency belongs to the test clock, not to a reconstructed timestamp.
3. Source totals71 local candidates,63 unconfirmed and6 confirmed leave **two outcomes unclassified**. Do not invent them or derive a precise classifier error rate. The7 bus detections are a usable bounded scenario; full-session percentages need original events.
4. Source conversation IDs exist at session level, but `voice.transcript`/`voice.assistant` were joined by time window. Do not claim recovered per-turn correlation. Rounded timestamps and reported tenths can disagree arithmetically; retain each as reported.
5. Historical pricing, model-default assumptions and backend claims are conversation content. They are not provider-truth assertions or current default recommendations.
6. Compare emitted decisions, task state, actual queue/gain/native calls, and ledger evidence. Do not configure a fake model to always emit the expected answer and call that proof the defect is fixed.
